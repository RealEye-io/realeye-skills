# RealEye data and metric definitions

> **Report rule:** the HTML report uses only VAI and its components (Reach, Speed, Hold). Raw metrics mentioned below (fixation ratio, TTFF, fixation time, counts) explain RealEye exports and must not appear in the report.


## Get the smallest useful evidence package

1. **One image item:** From Study > Results, use **Heatmap** beside the item. On the item Heatmap page, apply the intended participant filters, verify fixation vs gaze mode and the time slider, and export **AOI Overall Stats** from **Download**. Get the stimulus image and matching heatmap if needed. If the download opens an email-delivery prompt for a large export, have the user supply the resulting file. See [Heatmap Analyzer](https://www.realeye.io/support/how-to-analyze-heatmaps) and [CSV downloads](https://www.realeye.io/support/data-export-csv-files).
2. **Saved AOIs:** AOI CSVs need saved regions. If the image has none, ask the researcher to [make and save them in the Heatmap Analyzer](https://www.realeye.io/support/what-is-aoi) and confirm their shapes/windows before exporting. A header-only CSV is not evidence that nobody looked. Check per-AOI windows in the actual export; a heatmap screenshot's slider does not prove that the saved AOIs use the same interval.
3. **Native report, when available:** The **AOI VAI Report** on the image's AOI dashboard provides VAI components, AOI crops and overlays, and a VAI Speed ranking. Use **Print / Save as PDF** to obtain it. Use the per-window rows in preference to the summary average when evaluating a specific exposure. The nominal windows are `0.5-3 s`, `0.5-5 s`, and `0.5-10 s`, limited by stimulus duration. Read the actual bounds; short exposures can make two nominal windows identical. See [AOI Metrics](https://www.realeye.io/support/areas-of-interest-aois#content-aoi-vai-report-image-items).
4. **Extra exports only for a question they can answer:** Get **AOI Metrics per Participant** for exact hit counts, distributions, and groups; **AOI Fixations Order** for sequence; and **Quality Stats** for usability checks. If sequence timing or gaps outside AOIs matter, use time-stamped fixation evidence instead of inferring those details from a list of AOIs.
5. **Outcome comparison:** Request the [Survey Results CSV](https://www.realeye.io/support/csv-file-survey-results) or separate choice/field results with the scoring rules, variant assignment, and response counts. The CSV uses item-named question columns. Match the questions to the assigned version; use `study_id` and `participant_id` to join to that person's gaze only when this mapping is verified. For aggregate comparisons, report the survey base and gaze base separately; invalid gaze alone need not invalidate a survey response.
6. **Video:** Request the exact cut or timecoded frames, AOIs with their actual visibility windows, and timestamped metrics or replays for the relevant shots. Request actual viewing duration and skip data separately if retention matters. The native AOI VAI Report described above is for image items.

### Optional: public API exports

Use the [canonical API contract](https://app.realeye.io/docs/api) and [ET Platform agent guide](https://www.realeye.io/downloads/skills/et-platform-agent-guide/SKILL.md) for a repeatable workflow. The paths below are relative to `https://app.realeye.io/api2` and require `X-AUTH-TOKEN` from an authorized, API-enabled account. Use the user's configured secret only with that API; do not print it, include it in a report, or send it to the UI. No token is needed to analyze supplied exports.

| Need | Read-only path |
|---|---|
| Verify the item belongs to a known study | `GET /studies/{studyId}/stimuli` |
| Aggregate AOI metrics (start here) | `GET /studies/{studyId}/collected-data/eye-tracking/aois-all/overall-stats?itemId={itemId}` |
| Participant-by-AOI metrics | `GET /studies/{studyId}/collected-data/eye-tracking/aois-all/fixations-stats?itemId={itemId}` |
| AOI sequence | `GET /studies/{studyId}/collected-data/eye-tracking/aois-all/fixations-order?itemId={itemId}` |
| Item quality | `GET /studies/{studyId}/collected-data/quality-stats?itemId={itemId}` |
| Survey answers | `GET /studies/{studyId}/collected-data/survey` |

The item ID is not the study ID. If only a dashboard item link is provided and it cannot be opened, ask for the exports rather than enumerating studies or calling internal dashboard routes. `api2` does not provide the dashboard heatmap or native VAI report page. If the API denies access or the account lacks the API entitlement, use the supplied-file/dashboard workflow. Check response type, CSV headers, and item ID before interpreting any values.

## Read the aggregate fields

These are labels and commonly available [AOI Overall Stats](https://www.realeye.io/support/aoi-overall-stats-csv) headers. Inspect actual headers and `notes`; export versions may differ.

| Question | RealEye field | How to read it |
|---|---|---|
| Who is counted? | `participant_count` | Base for the item under the export filters. It is not the number who looked at each AOI. Do not sum it across AOI rows. |
| How many looked? | Fixation **Ratio**: `aoi_fixation_participant_ratio_percents` | Percentage of the item base with a qualifying fixation in the AOI/time range. The exported Ratio can be rounded. If exact counts are unavailable, write e.g. "58%; item base N=24", not a reconstructed integer numerator. **Relative Ratio** uses the subset with the opportunity to see the AOI. Keep the two separate if opportunity varies. |
| How soon did they find it? | Average **TTFF**: `aoi_fixation_average_ttff_ms` | Mean first qualifying fixation onset, from stimulus onset, **among fixators in that window**. A window starting at 500 ms still uses stimulus onset as time zero. Relative TTFF instead uses AOI visibility onset. If no one fixated, ordinary TTFF is unavailable, not zero or the exposure duration. |
| How much time was spent looking? | Fixation **Average Time Spent**: `aoi_fixation_average_total_time_spent_ms` | Mean of the time spent in qualifying fixations summed per AOI viewing, **among those with a fixation** (one exposure per person for the simple static-image case). Distinct from average duration of one fixation (`aoi_fixation_average_fixation_duration_ms`) and first fixation duration. Not time on or reading the whole stimulus. |
| How much activity/return? | `aoi_fixation_total_count`, `aoi_visit_total_count`, `aoi_revisit_total_count`, `aoi_revisit_average_count` | Counts depend on cohort size and viewing time. Visits can separate on a long data gap; revisits are visits after the first. Average revisits includes zeros. Avoid interpreting them as a count of people or proof of confusion. |
| How did attention build? | `aoi_visual_attention_index` and `aoi_vai_attention_reach`, `aoi_vai_attention_speed`, `aoi_vai_attention_hold` when present, or native report | **Measured VAI** is a 0-100 composite. Reach is relative to opportunity to see the AOI; Speed is a normalized timeliness score that accounts for non-fixators, not TTFF in ms; Hold relates fixation time (including people with zero fixation time) to AOI duration, not average dwell among fixators. Use supplied scores for their specific window; do not construct them from a heatmap or conditional averages. VAI scores across regions need not sum to 100. |
| Could geometry or time explain it? | `aoi_item_parts`, `aoi_size_overall_percents`, `aoi_time_range_from_ms`, `aoi_time_range_to_ms` | Check the boundaries, overlap, size as a percentage of the image, and actual calculation window. RealEye describes AOI fixation inclusion by fixation **start** time; do not derive a time slice by subtracting TTFF, hold, or other averages in different windows. |

Gaze Ratio, TTFG (time to first gaze), gaze time spent, and gaze point counts are different measures. Use them only when clearly labeled, not as a substitute in a fixation comparison. Clicks and time to first click are response metrics only if collected and meaningful for the task. Avoid using K coefficient or facial coding by default to infer attention quality or emotional response.

**Fixation-time share (optional derived diagnostic):** Sum the valid fixation milliseconds in the union of the brand and claim AOIs, and divide by all valid on-stimulus fixation milliseconds for the same people and time window. The rest includes on-stimulus fixations outside those AOIs. Use matched event data or validated totals, deduplicate overlaps, and report whether the proportion is pooled or averaged per participant. No denominator means unavailable. Do not build it by dividing conditional AOI averages or treating VAI as a time share.

## Verify the numbers before writing

- **Parsing and grain:** Use a CSV reader, not a comma split (AOI geometry, filenames and notes can contain commas). Match `study_id`, `item_id`, `aoi_id` and window, not just filenames or display names. Trim padding from headers and find the first populated `notes` cell for export settings. Header-only, truncated, or error exports require verification, not zero-filled summaries.
- **Eligibility:** Match the item cohort and filters across outputs. Keep device and tracking setups comparable; mouse-tracker data is not eye tracking. Use [item quality and sampling/integrity information](https://www.realeye.io/support/participant-quality-stats-explained) rather than the study-wide grade alone. Low sampling can leave gaze data but no computed fixations. Record sample before/after exclusions if known; apply the same justified quality rule across variants. If enough evidence exists, check whether the main conclusion holds under a stricter defensible filter. Without a verified base, do not calculate reach from hit rows alone.
- **Participant calculations:** For the usual one exposure per person, use one record per participant/item/AOI/window in [participant AOI statistics](https://www.realeye.io/support/download-aoi-data-to-csv-file). Verify distinct participant IDs against the eligible base. A positive `aoi_fixation_total_count` is a hit. For event-level exports (e.g. `fixation_starts_at_ms`), collapse by participant and AOI first; the earliest qualifying onset is that person's TTFF. Use RealEye's reported time-spent field when possible. For an explicitly *inclusive* mean, divide summed fixation time by the eligible base, with zero only for verified eligible misses. Handle repeated exposures separately or specify a participant-level rule before pooling. Flag inconsistent or ambiguous rows rather than silently counting them twice.
- **Sequence:** [AOI Fixations Order](https://www.realeye.io/support/aois-fixation-order-csv) represents observed AOI order per participant; entries may occupy trailing CSV cells under and after `aoi_fixations_order`. Confirm the time range and AOI mapping, particularly with repeated names or overlaps. Distinguish "first recorded AOI" from "first fixation on the image"; fixations outside saved AOIs are not represented. Report e.g. "Product was the first recorded AOI for 12 of 20 viewers with an identified AOI path; 24 viewers analyzed." The native VAI report's Speed ordering is a ranking, **not** participant paths or proof of transitions.
- **Sanity checks:** Check for `N=0`, missing/nonfinite values, percentages outside 0-100, implausible times, and cohort or window mismatches. Investigate discrepancies before reporting. Preserve `Unavailable` versus real zero. Convert ms to s only for display and use percentage points for rate differences. Do not compute a new denominator from rounded ratios, add overlapping AOI percentages, or average variant-level averages as though each had the same sample.
- **Heatmaps:** Confirm type (fixation or gaze), cohort, time, and render settings. [Colors show relative intensity, not numerical values or order](https://www.realeye.io/support/what-is-a-heatmap-viewmap). Even side-by-side maps with matching settings can use different intensity scaling; corroborate with the metrics before calling a difference.
